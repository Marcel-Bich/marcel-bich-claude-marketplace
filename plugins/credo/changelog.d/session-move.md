### Added

- `/credo:session-move` (command + skill `session-move`, `scripts/credo-session-move.py`): move Claude Code sessions, given by caption / custom title or full id, from one profile (`CLAUDE_CONFIG_DIR`) to another. Execution class C: only on the user's explicit invocation, from a new session that is not one of the moved ones
- `plan` (dry run) detects the setup instead of copying 1:1: the target layout (top-level symlinks shared with the source vs real entries) and, per artifact that exists for the id (transcript, `projects/<slug>/<id>/`, every entry whose name holds the full id), `COPY`, `PRESENT`, `SHARED` (target path resolves into the source through a symlink, never copied or cleaned up), `CONFLICT` or `BLOCKED` (symlink or special file in the source, target symlink to a third place, entry directly at the profile root, leftover `<file>.part` from an interrupted copy); short-id names are listed for review only, shared logs and profile-global config are never copied. Sessions whose files contain symlinks cannot be moved with this command
- Captions resolve from `custom-title.json` or the transcript's custom-title records, never from stale `sessions/*.json` pid files; ambiguous captions are refused, also when `custom-title.json` and the transcript disagree
- Refuses the current session (`CLAUDE_CODE_SESSION_ID`) and live sessions: a Claude process whose argv names the id, or a pid file naming the id in the source, the target or a sibling `.claude*` profile whose pid is alive (any process name; dead pids are stale; pid reuse is decided only by the pid file's `procStart` compared with `/proc/<pid>/stat` field 22 - mismatch ignored, match / absent / unreadable live, a recognised Claude process never ignored, no mtime or clock heuristic). Without `/proc` it falls back to `ps -axww` (every alive pid from a pid file counts as live, versioned binaries under `/claude/versions/` are recognised); when liveness cannot be determined it refuses. `--profile <dir>` (repeatable) adds profile dirs to the liveness scan; sessions started with another profile location and Windows-side sessions are not seen unless passed
- `copy`: one source per explicit target path via `<file>.part`, fsync and hard link (no overwrite, never a half-written target file), no symlink followed, mode and mtime kept; re-running after an interruption completes the copy. `verify`: size, sha256 and entry count with one read per file; a green verify records source and target size + sha256 in `<target>/credo/session-move/<id>.json`, refused sessions get no manifest
- `cleanup-script --user-confirmed` (after the user tested the resume and approved): a sh script with literal paths only inside the source profile that name the session id, in a new `mktemp` dir under `/tmp` (0700 / 0600). Source files whose target copy vanished or is no longer intact are left out and reported. Intact: the session's main transcript (append-only) may have grown but must still start with the verified content; every other file must have exactly the verified size and sha256. At run time a file is removed only while it still has the verified checksum, is not a symlink, its target copy is a regular file that is not the same file and is intact by that rule (transcript: `head -c` prefix + checksum; other files: `wc -c` + full checksum), and both its directory and the target directory still resolve to the recorded physical paths; directories only with `rmdir`. The script prints `removed N, kept M` and exits 1 when anything was kept; it is written under a temp name and renamed (a failed write removes only its own temp file and reports the dir). A manifest whose target size / checksum differs from the source values is rejected. Needs `sha256sum` or `shasum`. The user runs it; the agent never deletes
- A transcript cwd with control characters is not printed or put into the resume command (a warning replaces it). Every other string from the profile in the text output (custom titles, slugs, paths, reasons) is printed with control, bidi-format and surrogate characters escaped (`\xNN`), plus a warning for a title or slug that needed it; `--json` is unchanged
- Documented limits: the prefix rule applies to the transcript only and assumes it is append-only; a control character in any path refuses the whole script
- Added to the class C lists (session-start knowledge block, `/credo:session-init`)
- Fail-closed hardening: `credoPeerBridge` pid files count as live holders (only `credoPeerLan` relay mirrors are skipped); a `procStart` that is zero, negative or not an integer is unknown and counts as live; a name that holds a second full session id is BLOCKED (`names another session too`); unreadable or invalid pid files are listed as WARNING; the `/proc` test seam `CREDO_SESSION_MOVE_PROC_ROOT` is honoured only with `CREDO_SESSION_MOVE_TEST=1`; the manifest temp file is created exclusively (a stale `<id>.json.tmp` is refused, never truncated); unencodable cleanup script text is handled like a failed write
- Tests: `test-credo-session-move.sh` (separate and symlink-shared fake profiles, no-`/proc` fallback, interrupted copy, cleanup target checks)
