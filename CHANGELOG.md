# 2026-10

## credo

### v0

#### v0.82

##### v0.82.4

###### Changed

- The preset block carries a one-line rule for every subagent spawn. It points to `credo-preset.sh stage <role> <attempt>`, which supplies the model, effort and prompt.
- `init` warns when an added peer address is not reachable from this machine; a peer behind NAT should run `init` towards this machine instead, and the return channel carries the traffic
- A pending repair is dropped once its address is no longer a configured peer (daemon start, `init`, `check`, `pairs`); the pairing itself is never touched
- `check` adds a hint under a pending repair whose address is not reachable from this machine

###### Fixed

- Declining credo in a directory, or for a session, no longer hides the model preset. The SessionStart hook keeps injecting the preset instructions; only the items workflow stays off there.
- The preset block also reaches the main agent in a session that has not made a credo decision yet, and under the gsd task backend.
- The `/credo:disable` description states that model presets and shorthands stay on.
- `/credo:disable` also records the current session as declined, so a session that was already active stops getting the workflow text on resume and compact.
- A roster send to an unreachable peer is logged once when the peer goes down and once when it recovers, instead of on every roster interval
- `peer-lan.log` is rotated to a single `peer-lan.log.1` backup when it exceeds 5 MB, so the log no longer grows without bound

##### v0.82.3

###### Fixed

- A LAN peer that stays unreachable for hours no longer crashes the link thread on every retry: the link backoff overflowed after about a thousand failed attempts (`OverflowError`), so each attempt wrote a full traceback to the relay log and the backoff was never recorded

##### v0.82.2

###### Fixed

- `pair-reset` removes the peer's trust entries before the pairing; when a trust list cannot be read or an entry cannot be removed, the reset exits 1 and the pairing stays in place
- Keystore dirs and the holder relay socket are created without a process-wide `os.umask` change (the daemon no longer flips the umask while other threads run)
- The documented Windows setup runs the elevated `-Install` from a copy in `%TEMP%`: started straight from the `\\wsl.localhost` path, the elevated window could close at once without installing anything while reporting exit code 0
- The docs no longer say that the other machine may refuse a new pairing after `disconnect-all`; with this machine's peer id kept, it accepts it again at once

##### v0.82.1

###### Fixed

- LAN relay `disconnect-all` removes only pairing records (`peer-<id>.json` with a 32 hex char peer id) from a keystore dir. Other `peer-*.json` files in that dir, such as `peer-lan.json` or `peer-lan-trust.json` when `keys_dir` points at a profile's `credo/` dir, are no longer deleted or counted as pairings
- The relay's periodic pairing copy sync had the same name match and no longer removes those files either
- When `disconnect-all` fails while clearing a profile, a relay that was running is still restarted, and the command exits non-zero
- A quote in the scheduled task name is escaped in the `--full` Windows uninstall command

##### v0.82.0

###### Added

- LAN relay `disconnect-all` (`--dry-run`, `--yes`, `--full`) resets the relay to "no other device known": removes the pairings, pending repairs, trust grants, stored peer addresses and LAN mirrors of every served profile, then restarts the relay. It lists what goes and asks first; the slash command `/credo:peer-lan disconnect-all` explains it and asks before running it
- `disconnect-all --full` also removes the Windows-side setup under WSL (scheduled task, firewall rule, portproxy) through the setup's own `credo-peer-lan-winproxy.ps1 -Uninstall`, with one elevated prompt; elsewhere it is skipped with a note
- Kept by `disconnect-all`: this machine's identity, the bound networks and their allowlists, the `profiles` list, the listen settings and the token

###### Changed

- The kept reason for a fresh worktree without own commits reads `no commits yet (fresh worktree), created Nh ago - may be in use`

###### Fixed

- The automatic merged-worktree cleanup no longer removes a fresh worktree whose branch was only fast-forwarded to main (for example after a sync with main) and has no commit of its own. Such a branch was reported as "merged into main, clean" and removed at once, because the fast-forward added a second reflog entry that skipped the fresh-worktree guard
- A branch counts as having its own commits only when its reflog holds a commit, cherry-pick or revert entry; the 24h fresh guard (`--fresh-hours`) applies to every branch without them. A merged, clean branch with own commits is still removed at once, also when it was merged by fast-forward

#### v0.80

##### v0.80.0

###### Changed

- The session-move cleanup script decides by the source. A source file is removed while it is unchanged since the verify and its target copy exists as a regular file; a target that changed after the copy (the resumed session's transcript included) no longer keeps it. A missing or emptied target copy still keeps the source, and a changed source still refuses the cleanup.
- The LAN relay serves every Claude Code profile of the machine. The roster names the profile of each local session, every remote session is mirrored into each profile's `sessions/`, and a message reaches a session in any profile.
- Trusted peers are checked in the target session's own profile. A grant made in one profile never applies to a session in another profile.
- Duplicate caption detection covers all profiles of the sending machine.
- The pairing record is copied into the keystore of every profile of the machine. Trust is still granted per profile with `trust add` run in that profile, and `pair-reset` removes a pairing and the peer's trust from every profile.

##### v0.79.0

###### Added

- Model presets `quality`, `balanced` (default) and `budget` in `templates/presets.default.yaml`, selected with `preset: <name>` in the global or project config (project overrides global). Custom presets go under `presets:` with the same schema and may use any model; a same-named custom preset replaces the built-in one as a whole
- Each role (`explore`, `build`, `review`, `hard`) is one stage `{model, effort, attempts, subagent-prompt}` or a chain of stages that may end with `back-to-human`; `attempts` is a positive number or `until-done` (no attempt cap, budget caps and a repeated failure without progress stop it)
- `scripts/credo-preset.sh` resolves the active preset: `stage <role> [attempt]` prints the model, the Agent-tool alias, the effort, the prompt block and the next action (retry, next-stage or back-to-human); `mainagent`, `show [name]`, `list` and `active` cover the rest. Invalid parts print a warning and fall back to balanced for that role; missing prompt keys add nothing
- Prompts: `universal-prompt` for every agent, `mainagent-prompt` for the main agent (delivered by the SessionStart hook of an active session, also after a compaction; `/credo:session-active` and `/credo:session-init` print it once for a mid-session start) and a per-stage `subagent-prompt` that the main agent appends when it spawns a subagent, because the SubagentStart hook carries neither the role nor the prompt. A builder that may decide agent-owned questions also gets the `mainagent-prompt` in its brief
- Back-to-human: the item moves to `1_clarify` with a `> URGENT:` note and an ntfy push; an autonomous run continues with other items, an attended session asks the user
- `/credo:setup` Step 2d presents the built-in presets and lets the user pick one or describe a custom one (written into the chosen config and verified with `credo-preset.sh show`); `/credo:session-init` hints, read-only, when the main model differs from the preset recommendation
- `credo-config.sh`: the built-in presets as a builtin layer, flow-map syntax (`{key: value}`) in the stdlib YAML parser, and `CREDO_CONFIG_STDLIB_YAML=1` to force that parser
- `credo-item-move.sh` accepts the neutral agent decision marker `(GO: agent decision, <reason>)`; the older `(GO: agent per SOTA rule, <reason>)` stays accepted
- Tests: `test-credo-preset.sh` (helper, validation, config layering, SessionStart injection, doc invariants); `test-item-move.sh` covers both GO markers
- `/credo:session-move` (command + skill `session-move`, `scripts/credo-session-move.py`): move Claude Code sessions, given by caption / custom title or full id, from one profile (`CLAUDE_CONFIG_DIR`) to another. Execution class C: only on the user's explicit invocation, from a new session that is not one of the moved ones
- `plan` (dry run) detects the setup instead of copying 1:1: the target layout (top-level symlinks shared with the source vs real entries) and, per artifact that exists for the id (transcript, `projects/<slug>/<id>/`, every entry whose name holds the full id), `COPY`, `PRESENT`, `SHARED` (target path resolves into the source through a symlink, never copied or cleaned up), `CONFLICT` or `BLOCKED` (symlink or special file in the source, target symlink to a third place, entry directly at the profile root, leftover `<file>.part` from an interrupted copy); short-id names are listed for review only, shared logs and profile-global config are never copied. Sessions whose files contain symlinks cannot be moved with this command
- Captions resolve from `custom-title.json` or the transcript's custom-title records, never from stale `sessions/*.json` pid files; ambiguous captions are refused, also when `custom-title.json` and the transcript disagree
- Refuses the current session (`CLAUDE_CODE_SESSION_ID`) and live sessions: a Claude process whose argv names the id, or a pid file naming the id in the source, the target or a sibling `.claude*` profile whose pid is alive (any process name; dead pids are stale; pid reuse is decided only by the pid file's `procStart` compared with `/proc/<pid>/stat` field 22 - mismatch ignored, match / absent / unreadable live, a recognised Claude process never ignored, no mtime or clock heuristic). Without `/proc` it falls back to `ps -axww` (every alive pid from a pid file counts as live, versioned binaries under `/claude/versions/` are recognised); when liveness cannot be determined it refuses. `--profile <dir>` (repeatable) adds profile dirs to the liveness scan; sessions started with another profile location and Windows-side sessions are not seen unless passed
- `copy`: one source per explicit target path via `<file>.part`, fsync and hard link (no overwrite, never a half-written target file), no symlink followed, mode and mtime kept; re-running after an interruption completes the copy. `verify`: size, sha256 and entry count with one read per file; a green verify records source and target size + sha256 in `<target>/credo/session-move/<id>.json`, refused sessions get no manifest
- `cleanup-script --user-confirmed` (after the user tested the resume and approved): a sh script with literal paths only inside the source profile that name the session id, in a new `mktemp` dir under `/tmp` (0700 / 0600). Source files whose target copy vanished or is no longer intact are left out and reported. Intact: the session's main transcript (append-only) may have grown but must still start with the verified content; every other file must have exactly the verified size and sha256. At run time a file is removed only while it still has the verified checksum, is not a symlink, its target copy is a regular file that is not the same file and is intact by that rule (transcript: `head -c` prefix + checksum; other files: `wc -c` + full checksum), and both its directory and the target directory still resolve to the recorded physical paths; directories only with `rmdir`. The script prints `removed N, kept M` and exits 1 when anything was kept; it is written under a temp name and renamed (a failed write removes only its own temp file and reports the dir). A manifest whose target size / checksum differs from the source values is rejected. Needs `sha256sum` or `shasum`. The user runs it; the agent never deletes
- A transcript cwd with control characters is not printed or put into the resume command (a warning replaces it). Every other string from the profile in the text output (custom titles, slugs, paths, reasons) is printed with control, bidi-format and surrogate characters escaped (`\xNN`), plus a warning for a title or slug that needed it; `--json` is unchanged
- Documented limits: the prefix rule applies to the transcript only and assumes it is append-only; a control character in any path refuses the whole script
- Added to the class C lists (session-start knowledge block, `/credo:session-init`)
- Fail-closed hardening: `credoPeerBridge` pid files count as live holders (only `credoPeerLan` relay mirrors are skipped); a `procStart` that is zero, negative or not an integer is unknown and counts as live; a name that holds a second full session id is BLOCKED (`names another session too`); unreadable or invalid pid files are listed as WARNING; the `/proc` test seam `CREDO_SESSION_MOVE_PROC_ROOT` is honoured only with `CREDO_SESSION_MOVE_TEST=1`; the manifest temp file is created exclusively (a stale `<id>.json.tmp` is refused, never truncated); unencodable cleanup script text is handled like a failed write
- Tests: `test-credo-session-move.sh` (separate and symlink-shared fake profiles, no-`/proc` fallback, interrupted copy, cleanup target checks)
- `scripts/credo_session_name.py`: one small resolver for every peer / session name credo shows, with a single fallback order: caption, kitty tab title, tmux session, short session id. Every name is capped at 20 characters and keeps only letters, digits, space, `.`, `_` and `-` (NFC), whichever step supplies it. The caption is a user-set name only: for Claude the registry `name` when `nameSource` is `user` (the cwd-based `derived` name never counts), for Codex the newest `thread_name` row of `$CODEX_HOME/session_index.jsonl` for the thread id (read without following symlinks, regular file owned by the current user, last 256 KiB only, sanitized). A daemon-hosted Claude session has no tmux or kitty ancestry of its own, so its labels are resolved through its verified client TUI (fail closed)
- The tmux pane and client lists are reused for 15 seconds across lookups (the LAN roster builds a new lookup on every tick), and one lookup spends at most about 2 seconds in kitty remote-control calls in total
- Tests: `test-credo-session-name.sh`
- Worktree cleanup opt-out: `git worktree lock --reason "keep: owner" <path>` keeps a worktree. `credo-worktree-cleanup.sh` never removes a locked worktree and reports it as `kept <path> branch=<b> reason=locked: <lock reason>` (normal, `--dry-run` and JSON with `lock_reason`; a locked worktree whose directory is gone is reported as locked, not as prunable)
- `credo-worktree-cleanup.sh --keep <path|branch>` (repeatable) keeps a worktree for a single run; a `--keep` that matches no worktree warns on stderr
- `credo-worktree-cleanup.sh --list-locked [--json]` lists the locked worktrees with their reasons (no base branch needed)

###### Changed

- LAN trusted peers key on the session caption only: the name the user set with `/rename` (registry `nameSource` `user`, letters, digits, space `.` `_` `-`, at most 20 characters). The sending relay resolves it from its own session registry and sends it as `from_caption`; the free-form `from-name` the sending harness writes is display text only and can no longer earn trust. Sessions without a caption can still message but never hold trust
- `trust add <peer> <caption>` stores the caption in exactly the form the sending relay sends (filtered, whitespace collapsed, cut at 20 characters) and says so when that differs from the input, so a longer `/rename` still matches; a name with no caption characters is refused with the rule. `trust remove` accepts the typed or the stored form
- The trust marker is bound to the caption, the receiving session and the time (`from-caption` and `credo-trust-ts` in the opening tag, marker format v2): it verifies only in the session it was made for and for 10 minutes
- The LAN `from-name` is the sender's display name (caption, else short id from the holder; the daemon swaps in its roster-tick name with kitty / tmux labels), filtered to the same character set and capped at 20 characters. A deliver never waits on tmux or kitty
- `trust add` and `trust list` print a WARNING when a caption contains characters that look like plain Latin letters (Cyrillic or Greek lookalikes and similar, or characters NFKC folds, such as fullwidth letters); warning only, every script stays allowed
- The orchestration skill's model policy ("no downgrade, no model-choice logic") is replaced by the preset rules: the main agent picks model and effort per role from the active preset, follows the chains, and hands the item back when a chain is used up
- The agent decision philosophy (SOTA, else best effort, else note it) moved out of the items, orchestration, session-active, session-autonomous, role-plan and migrate skills and the credo guide into the preset's `mainagent-prompt`. The skills keep the fixed rules: who decides (human-owned or agent-owned), the GO line requirement, and the safety calls (user taste, deleting user data, installs, money, changes to the verbatim requirement)
- Worktrees for every code track, also a single isolated build track and not only parallel ones: `credo-worktree-flow.sh` runs before any worktree run. Under hydra the Agent tool's `isolation: "worktree"` is never used, and a bare `git worktree add` without the setup script is never run; always hydra's create flow plus its setup
- LAN relay rosters announce the resolved name instead of the registry name, and the peer check (`credo-peer-check.py`) lists Claude and Codex sessions under the same order; a session that nobody named is no longer shown under its cwd-based derived name (for example a host-and-suffix name) but under its kitty tab or tmux session, or its short id when it runs outside tmux and kitty. Peer trust keys on the user-set caption only (see the caption trust entry)
- Peer check: an unnamed Codex thread takes the tmux session of the one free Codex pane (when exactly one pane and one unnamed thread exist; otherwise it keeps its short id), and a live socket without a registry descriptor is named by the same order (kitty tab, tmux session, else `pid N`)
- `sid_short` moved from `credo-peer-lan.py` into `credo_session_name.py` (still importable from `credo-peer-lan.py`); a roster entry without a name is mirrored under its short id instead of the full session id
- Skills `items`, `safety`, `orchestration`, `session-autonomous`, README and credo guide: when the user says to keep a worktree the agent locks it with the reason `keep: owner`, names the kept worktrees before an item close, and unlocks only by this rule: autonomous mode may unlock a `keep: owner` lock itself once the keep reason no longer applies, every other mode asks first via the Ask tool, and a lock with another reason is never unlocked on its own

###### Fixed

- `credo_session_name.clean` normalizes to NFC again after filtering, so it is idempotent (a removed character between decomposed Hangul jamo no longer leaves a non-NFC name)
- A message body holding a lone surrogate no longer fails the inject of a trusted deliver (the marker hashes with `surrogatepass`)
- Several registry descriptors on one socket path (a stale one next to the live one): the sending relay uses the live one

###### Security

- The sending relay sends a caption only when the process that wrote the message into its proxy socket (`SO_PEERCRED`) is the captioned session's process or a child of it; another local process naming a session's reply socket gets no caption (its message is still delivered, untrusted)
- Duplicate captions fail closed: while 2+ live sessions of the sending relay's profile share a caption (case-insensitive; sessions without a messaging socket count too), the relay sends no caption, trust for it is suspended and the message carries a one-line notice to rename one session. Other profiles on the same machine are not checked yet
- Removing the last trust entry of a peer rotates the trust key, so a re-added grant never revives an older marker
- The trust file is opened without following a symlink and without blocking, and used only when it is a regular file of this user that is not group or world writable; `trust add` / `trust remove` change it under an exclusive lock (`peer-lan-trust.json.lock`) and abort with exit 1, changing nothing, when it exists but is unsafe or cannot be parsed
- The machine label in the hook's trusted-peer text is limited to `A-Z a-z 0-9 . _ -`, at most 24 characters
- Documented limits: same-user processes can read the trust key (the user account is the trust boundary), and a hostile paired relay can claim any caption and omit the duplicate flag (the caption is reported, not cryptographically proven)
- Migration: grants made before this change (keyed on the from-name) no longer match; `trust list` shows them as `LEGACY, inactive`. Give each trusted session a caption with `/rename`, re-add it once with `trust add <peer> <caption> --yes`, then drop the old entry with `trust remove <peer> <old name>`

###### Changed

- compact-plus and session-autonomous: in autonomous mode the first compact-plus ACTION already leads to compact-plus plus the self-compact (`credo-self-compact.py run --auto`) right after a green report, without asking, unless something important speaks against it; the ACTION is for the main session only, a subagent that sees one ignores it
- self-reload, self-compact and self-restart: when no input box is visible, the pane guard now names the cause in the log ("permission prompt open, waiting for the user: ..." or "no input box, dialog or menu open: ...") instead of only "no empty prompt input box visible". A permission prompt raised by a background agent replaces the input box in the main pane while the session itself looks idle; this, not the footer layout, made the workers wait until their 1800 s timeout
- self-reload, self-compact and self-restart: a classified dialog or permission prompt that blocks the pane for 120 s (`CREDO_SELF_RELOAD_BLOCKED_NOTIFY`, `CREDO_SELF_COMPACT_BLOCKED_NOTIFY`, `CREDO_SELF_RESTART_IDLE_BLOCKED_NOTIFY`; 0 = off) now sends one early ntfy push per blocked wait asking to answer it (without the dialog text); the generic "no input box" state (maybe a pane that is not Claude Code) never counts as blocked; the worker keeps waiting and continues by itself once the dialog is closed. Dialogs are still never typed into
- Peer trust guard is quiet by default: a recognized peer trust grant (Bash or Write/Edit/MultiEdit) no longer returns a permission "ask" - which overrode allow rules and bypass mode and blocked autonomous runs with peers - but a non-blocking reminder that only the user grants trust and that an unrequested grant must be revoked right away (`trust remove`) and reported. Strict mode (confirm every grant) via config `peer.trust_guard.quiet: false` or env `CREDO_PEER_TRUST_GUARD_QUIET=false` (env wins); the key is read from the global and profile layers only, so a repo's `.credo/config` cannot downgrade it; without python3 the config is not read and only the env variable selects strict mode; strict mode also asks on obfuscated forms (arguments from variables or command substitution, `$'...'`, brace expansion, globs, `eval`, `bash -c` with variable code, a trust file name built from variables or string pieces); the guard is documented as a best-effort reminder, not a security boundary; `/credo:setup` Step 12 explains the switch and sets it on request, `check-setup.sh` reports it (`peer_trust_guard`)
- Sender metadata line of incoming peer messages is labelled self-reported and unverified; each key=value pair is validated on its own (same whitelist as `credo_peer_meta.py`): no brackets except a context suffix like `[1m]` on the model, status only `idle`, `busy` or `waiting`

###### Fixed

- Peer trust guard false positives: a shell-aware parser (`scripts/credo_trust_guard.py`) replaces the text match. It flags a run of `credo-peer-lan.py` with `trust` and later `add` (direct, via python3, wrappers or a variable command word) and writes to the trust file (redirects, cp/mv/tee/ln/install/rsync/dd, sed -i, perl -i, truncate, rm, chmod, interpreter code with the file as a path literal), but no longer mentions: read-only commands (cat, grep, jq, ls), commit messages, echo strings and heredoc bodies such as a python3 heredoc editing another JSON doc. Unparsable commands get a cautious line check; without python3 the old text match applies

###### Security

- Metadata is informational only: every value passes a strict whitelist (enums including status, short fixed charset, model brackets only as a trailing context suffix such as `[1m]`, unknown keys dropped) and it never reaches the message envelope, trust, routing or any permission decision

- One deduplicated token ledger (`scripts/usage-ledger.sh`) for main agent and subagents: transcript lines are counted once per API message (`message.id` + `requestId`, last line wins), read incrementally without consuming a partial trailing line, and summed into 5-minute buckets so window tokens come from timestamps
- `[Est100%:X]` on the 5h / 7d device lines: median of window tokens / (API% / 100) over samples at >= 20 % in the current window, falling back to the previous window (`~`). It is a per-device value (only this device's transcripts are readable, API% is account-wide) and a lower bound with parallel use on other devices; no samples are taken while the transcript backfill is incomplete or the API numbers are older than `CLAUDE_MB_LIMIT_EST_MAX_AGE` (default 120 s)

- Tokens line shows the session sums (main agent + its subagents) from the ledger: Input incl. cache writes, Output, Cached (cache reads); it falls back to `LastReq` (last request from stdin) when the ledger is unreadable
- Window tokens, highscores and LifetimeTotal count work tokens (input + output + cache writes); cache reads are tracked and shown separately
- LifetimeTotal and `/limit:highscore` price usage per concrete model id with cache writes by TTL; models without a known price show `$X+n/a` instead of Opus pricing
- Window resets are also detected on a sharp utilization drop (> 20 points or below half) with an unchanged `resets_at`, and when `resets_at` has passed
- All state read-modify-writes run under a lock with atomic writes; an unreadable state skips the local values for one render instead of counting from 0

- `/limit:highscore` uses `CLAUDE_MB_LIMIT_DEVICE_LABEL` and shows Est100%, window tokens with cache reads and a per-model lifetime breakdown
- Transcript reading is linear in the bytes read (grep prefilter, one streaming jq pass, one awk pass for dedup and sums) and always bounded: the render reads about `CLAUDE_MB_LIMIT_SESSION_SCAN_BYTES` (default 2 MiB) of the current transcript per render (a single longer line is read whole), the global scan runs detached with a time budget (default 25 s, checked with millisecond resolution) (optional byte budget `CLAUDE_MB_LIMIT_SCAN_BYTES`), small transcripts are read in batches, and both resume from stored byte offsets with unfinished files marked pending, so a first backfill never blocks the statusline. The render-time scan is gated per transcript and writes nothing when the transcript did not grow; entries of deleted transcripts are pruned (lifetime totals stay; a transcript read or marked pending in the same run is never pruned). Transcript paths are canonicalized, so one file is never counted under two spellings.
